# PQA Framework — กรอบ Logic การทำงานของระบบ

## นิยาม PQA

**PQA = Performance–Quality Alignment**

ระบบประเมินผลการปฏิบัติงานที่เชื่อมโยงโดยตรงกับระบบประกันคุณภาพอย่างเป็นระบบ

หรือในเชิงปฏิบัติ:

> **PQA คือการทำให้การประเมินผล ไม่ใช่แค่ให้คะแนน แต่เป็นหลักฐานเชิงคุณภาพที่ยืนยันว่าองค์กรกำลังพัฒนาอย่างแท้จริง**

---

## นิยามเชิงวิชาการ (สำหรับงานวิจัย)

**PQA (Performance–Quality Alignment Model)** หมายถึง รูปแบบการบูรณาการระบบการประเมินผลการปฏิบัติงาน (Performance Assessment) เข้ากับระบบประกันคุณภาพการศึกษา (Quality Assurance) โดยเชื่อมโยงตัวชี้วัดรายบุคคลกับตัวบ่งชี้ระดับองค์กร เพื่อให้เกิดการพัฒนาอย่างต่อเนื่องและมีหลักฐานเชิงประจักษ์รองรับ

---

## โมเดล PQA 4 องค์ประกอบ

PQA สามารถอธิบายเป็นโมเดล 4 องค์ประกอบที่ทำงานเชื่อมกัน ดังนี้

```
                    ┌─────────────────────────────────────────┐
                    │     PQA = Performance–Quality Alignment  │
                    └─────────────────────────────────────────┘
                                          │
    ┌─────────────────────────────────────┼─────────────────────────────────────┐
    │                                     │                                     │
    ▼                                     ▼                                     ▼
┌───────────────┐  ┌───────────────────────────────┐  ┌───────────────┐  ┌───────────────┐
│ ๑ หลักฐาน    │  │ ๒ ตัวชี้วัดและความเชื่อมโยง   │  │ ๓ กระบวนการ   │  │ ๔ ผลลัพธ์และ  │
│   (Evidence) │──│   (Indicators & Alignment)     │──│   ประเมิน     │──│   การพัฒนา    │
│               │  │                               │  │ (Assessment)  │  │ (Development) │
└───────────────┘  └───────────────────────────────┘  └───────────────┘  └───────────────┘
         │                         │                           │                    │
         └─────────────────────────┴───────────────────────────┴────────────────────┘
                                    ( flow ข้อมูลและผลลัพธ์ )
```

### องค์ประกอบที่ 1: หลักฐาน (Evidence)

| รายการ | คำอธิบาย |
|--------|----------|
| **ความหมาย** | หลักฐานเชิงประจักษ์ที่แสดงการปฏิบัติงานหรือผลงานจริง (เอกสาร ภาพ วิดีโอ ลิงก์ ฯลฯ) |
| **บทบาทใน PQA** | เป็น “ฐานร่วม” — ชิ้นเดียวกันใช้รองรับได้ทั้งการประเมินคุณภาพ (QA) และการประเมินผลการปฏิบัติงาน (PA) |
| **ในระบบ** | โมเดล `Evidence` + `EvidenceFile`; การสร้างจากฟอร์มหลักฐาน หรือจาก **เก็บงาน (Work Collection)**; รองรับหลาย storage type (URL, YouTube, GDrive, Canva, Link) |
| **หลักการ** | สร้างครั้งเดียว ผูกตัวชี้วัดได้หลายด้าน → ลดการทำหลักฐานซ้ำและส่งเสริมการพัฒนาต่อเนื่อง |

### องค์ประกอบที่ 2: ตัวชี้วัดและความเชื่อมโยง (Indicators & Alignment)

| รายการ | คำอธิบาย |
|--------|----------|
| **ความหมาย** | โครงสร้างตัวชี้วัดระดับองค์กร (QA) และระดับรายบุคคล (PA) รวมถึงการ “ผูก” หลักฐานเข้ากับตัวชี้วัดเหล่านั้น |
| **บทบาทใน PQA** | ทำให้หลักฐานไม่ลอยตัว — ทุกชิ้นเชื่อมกับมาตรฐาน/ตัวชี้วัดชัดเจน จึงใช้ขับเคลื่อนทั้งความพร้อม QA และคะแนน PA ได้ |
| **ในระบบ** | **QA:** `EduLevel` → `QAStandard` → `QAIndicator`; Evidence ผูกผ่าน `indicatorId` / `indicatorCodes` • **PA:** `PAAspect` → `PAIndicator` → `PAAgreementItem`; Evidence ผูกผ่าน `PAEvidenceMapping` (และ challenge consideration) • **AI วิเคราะห์หลักฐาน** ช่วยแนะนำตัวชี้วัด (QA) ให้ผูกได้ตรงขึ้น |
| **หลักการ** | หลักฐานหนึ่งชิ้นอาจสัมพันธ์กับหลายตัวชี้วัด (QA และ/หรือ PA) ได้ผ่านการ mapping ที่ออกแบบไว้ |

### องค์ประกอบที่ 3: กระบวนการประเมิน (Assessment Process)

| รายการ | คำอธิบาย |
|--------|----------|
| **ความหมาย** | กระบวนการที่ใช้หลักฐานและตัวชี้วัดเพื่อ “ประเมิน” ทั้งในมิติ QA (ความพร้อม เกณฑ์ผ่าน) และ PA (ข้อตกลง คะแนน ผ่าน/ไม่ผ่าน) |
| **บทบาทใน PQA** | เป็นตัวเชื่อมระหว่างหลักฐาน+ตัวชี้วัด กับ “ผลลัพธ์” — ทำให้การประเมินเป็นไปเพื่อพัฒนา ไม่ใช่แค่รายงาน |
| **ในระบบ** | **QA:** Completeness (รวบรวมหลักฐานต่อตัวชี้วัด → คะแนนต่อ domain), Pass criteria (เกณฑ์ผ่านต่อรอบ), Development Summary (รวบรวมข้อมูลสำหรับสรุป) • **PA:** สร้าง/แก้ไขข้อตกลง PA, ให้คะแนนรายตัวชี้วัดและประเด็นท้าทาย, ผูกหลักฐานกับรายการ PA, คำนวณคะแนนและสรุปผ่าน/ไม่ผ่าน |
| **หลักการ** | กระบวนการเดียวกันใช้หลักฐานชุดเดียวกัน — QA ดูที่ความพร้อมต่อมาตรฐาน, PA ดูที่ผลการปฏิบัติต่อข้อตกลง |

### องค์ประกอบที่ 4: ผลลัพธ์และการพัฒนา (Results & Development)

| รายการ | คำอธิบาย |
|--------|----------|
| **ความหมาย** | ผลที่ได้จากการประเมิน (รายงาน ความพร้อม สรุป PA, PowerPoint สรุปพัฒนาการ) และการนำผลไปใช้เพื่อการพัฒนาต่อเนื่อง |
| **บทบาทใน PQA** | แปล “การประเมิน” เป็น “การพัฒนา” — ใช้ผลเพื่อวางแผน ปรับปรุง และสื่อสารกับหน่วยงาน/ผู้ตรวจ ไม่ใช่จบแค่คะแนน |
| **ในระบบ** | **QA:** รายงานความพร้อม, รายการตัวชี้วัดที่ขาดหลักฐาน, Development Summary ต่อโรงเรียน/ครู/ปี/รอบ, สร้าง PowerPoint (pptx-generator) • **PA:** สรุป PA ครู/ผู้บริหาร, คะแนนรวม ผ่าน/ไม่ผ่าน, ใช้ประกอบการพัฒนารายบุคคล |
| **หลักการ** | ผลลัพธ์มาจากหลักฐานและตัวชี้วัดที่เชื่อมกันแล้ว จึงเป็น “หลักฐานเชิงคุณภาพที่ยืนยันการพัฒนาอย่างแท้จริง” ตามนิยาม PQA |

---

### ความสัมพันธ์ระหว่าง 4 องค์ประกอบ

| จาก → ไป | ความสัมพันธ์ |
|----------|----------------|
| **๑ → ๒** | หลักฐานถูกผูกกับตัวชี้วัด (QA และ/หรือ PA) ผ่าน indicatorId, indicatorCodes, PAEvidenceMapping |
| **๒ → ๓** | ตัวชี้วัดและความเชื่อมโยงเป็นฐานให้กระบวนการประเมิน (completeness, pass criteria, ข้อตกลง PA, การให้คะแนน) |
| **๓ → ๔** | กระบวนการประเมินผลิตผลลัพธ์ (รายงานความพร้อม, Development Summary, สรุป PA, PowerPoint) |
| **๔ → ๑** | ผลลัพธ์และ feedback นำไปสู่การสร้าง/เลือกหลักฐานชิ้นใหม่หรือปรับปรุงหลักฐานเดิม (วงจรพัฒนา) |

โมเดล 4 องค์ประกอบนี้ใช้เป็น **กรอบอ้างอิง** สำหรับออกแบบฟีเจอร์ อธิบายผู้ใช้ หรือเขียน Conceptual Framework ในงานวิจัยได้

## แนวคิดเชิงลึก: PA vs QA

| มิติ | PA (Performance Assessment) | QA (Quality Assurance) |
|------|-----------------------------|-------------------------|
| **วัดอะไร** | การปฏิบัติจริง | ระบบ / มาตรฐาน |
| **โฟกัส** | ผลลัพธ์เชิงพฤติกรรม ผลงาน ตัวชี้วัดรายบุคคล/หน่วยงาน | ความสอดคล้อง มาตรฐาน กระบวนการ |
| **ระดับ** | รายบุคคล / หน่วยงาน | องค์กรโดยรวม |
| **ในระบบ** | ข้อตกลง PA, ตัวชี้วัด PA, การให้คะแนนรายตัวชี้วัด | ตัวชี้วัด QA, หลักฐานต่อมาตรฐาน, ความพร้อม, รายงาน |

เมื่อรวมเป็น **PQA** ระบบจะทำให้:

| จากเดิม | กลายเป็น |
|--------|----------|
| ประเมินเพื่อรายงาน | ประเมินเพื่อพัฒนา |
| หลักฐานกระจัดกระจาย | หลักฐานเชื่อมโยงตัวชี้วัด (QA + PA) |
| ครูถูกประเมิน | ครูเป็นเจ้าของคุณภาพ |
| QA ทำตอนใกล้ตรวจ | QA เกิดตลอดปี (หลักฐานสะสมต่อตัวชี้วัด) |

## กรอบ Logic การทำงานของระบบ (PQA Logic)

ระบบนี้ใช้ PQA เป็นกรอบออกแบบ Logic ดังนี้

### 1. หลักฐานหนึ่งชิ้น รองรับได้ทั้ง QA และ PA

- **Evidence** = หน่วยหลักของ “หลักฐาน” ในระบบ
- หลักฐานหนึ่งชิ้นสามารถ:
  - ผูกกับ **ตัวชี้วัด QA** (ผ่าน `indicatorId` / `indicatorCodes`) → ใช้ในรายงานความพร้อม QA, Development Summary
  - ผูกกับ **รายการ PA** (ผ่าน **PAEvidenceMapping**) → ใช้ประกอบการประเมิน PA รายบุคคล
- ดังนั้น **หลักฐานไม่ซ้ำซ้อน**: สร้างครั้งเดียว ใช้ได้ทั้งประกันคุณภาพและประเมินผลการปฏิบัติงาน

### 2. QA: ระดับองค์กร (มาตรฐาน / ตัวชี้วัด / ความพร้อม)

- **EduLevel → QAStandard → QAIndicator** = โครงสร้างตัวชี้วัด QA
- **Evidence** ต้องเชื่อมกับ **QAIndicator** (หรือรหัสใน `indicatorCodes`) เพื่อนับในความพร้อม
- Logic ที่เกี่ยวข้อง:
  - **Completeness** (`lib/indicators/completeness.ts`): รวบรวมหลักฐานต่อตัวชี้วัด → คำนวณ score ต่อ domain → ประเมินเกณฑ์ผ่านตาม round
  - **Pass criteria** (`lib/indicators/pass-criteria.ts`): เกณฑ์ผ่านต่อรอบ (วิชาชีพ/สังคม/บุคคล)
  - **Development Summary**: สรุปผลพัฒนาต่อโรงเรียน/ครู/ปี/รอบ และสร้าง PowerPoint

### 3. PA: ระดับรายบุคคล (ข้อตกลง / ตัวชี้วัด PA / คะแนน)

- **PAAspect → PAIndicator → PAAgreementItem** = โครงสร้างข้อตกลง PA
- **PAAgreement** = ข้อตกลง PA ต่อคนต่อปี (และตำแหน่ง ถ้ามี positionType)
- **PAEvidenceMapping** = เชื่อม **Evidence** กับ **PAAgreementItem** หรือ **PAChallengeConsideration**
- Logic ที่เกี่ยวข้อง:
  - สร้างข้อตกลง PA → กรอกคะแนน/ความเห็นต่อตัวชี้วัด → ผูกหลักฐานผ่าน PA Evidence Mapping
  - คำนวณคะแนน PA (ส่วน 1 + ส่วน 2) → สรุปผ่าน/ไม่ผ่าน
  - สรุป PA ครู → รวมเป็น PA ผู้บริหาร (ถ้ามี)

### 4. Flow หลักฐานในระบบ (PQA Flow)

```
[ครู/ผู้ใช้สร้างหลักฐาน] → Evidence (ผูก QAIndicator / indicatorCodes)
        │
        ├──→ QA: ใช้ใน Completeness, Development Summary, รายงานความพร้อม
        │
        └──→ PA: ผ่าน PAEvidenceMapping ผูกกับ PAAgreementItem / Challenge
                    → ใช้ประกอบการให้คะแนน PA และสรุปผล
```

- **เก็บงาน (Work Collection)** → สร้าง Evidence จากงานที่มีอยู่ → ผูกตัวชี้วัด (QA) และ/หรือผูก PA ภายหลัง
- **AI วิเคราะห์หลักฐาน** → ช่วยสรุปและแนะนำตัวชี้วัด (QA) เพื่อให้หลักฐาน “เชื่อมตัวชี้วัด” ได้ชัดขึ้น

---

## การตีความ PQA ในระบบ (คำถามชวนคิด)

- **ถ้า PA ไม่เชื่อม QA** → หลักฐานอาจเป็นแค่ “เอกสารประกอบ PA” ไม่ขับเคลื่อนความพร้อม QA
- **ถ้า QA ไม่เชื่อม PA** → หลักฐานอาจเป็นแค่ “แฟ้มรับการตรวจ” ไม่สะท้อนการปฏิบัติจริงรายคน
- **เมื่อออกแบบ PQA ดี** → หลักฐานหนึ่งชิ้นมีคุณค่าทั้งต่อมาตรฐาน (QA) และต่อการประเมินบุคคล (PA) = มุ่งสู่ “วัฒนธรรมองค์กรที่พัฒนาอย่างต่อเนื่อง”

---

## สรุปการแมป PQA กับระบบเทคนิค

| แนวคิด PQA | ในระบบ (โมเดล/ฟีเจอร์) |
|------------|-------------------------|
| หลักฐานร่วม (Evidence) | `Evidence` + `EvidenceFile` |
| QA – ตัวชี้วัดองค์กร | `QAIndicator`, `indicatorId`, `indicatorCodes` บน Evidence |
| QA – ความพร้อม / สรุป | `completeness.ts`, `pass-criteria.ts`, `development-summary.ts`, `pptx-generator.ts` |
| PA – ข้อตกลงรายคน | `PAAgreement`, `PAAgreementItem`, `PAChallengeItem`, `PAChallengeConsideration` |
| PA – ตัวชี้วัด PA | `PAIndicator`, `PAAspect` |
| การเชื่อมหลักฐานกับ PA | `PAEvidenceMapping` (evidenceId ↔ agreementItemId / challengeConsiderationId) |
| การวิเคราะห์เพื่อเชื่อมตัวชี้วัด | POST `/api/evidence/[id]/analyze` (AI สรุป + แนะนำตัวชี้วัด) |

### แมปโมเดล PQA 4 องค์ประกอบกับระบบ

| องค์ประกอบ | โมเดล/ฟีเจอร์หลักในระบบ |
|------------|---------------------------|
| ๑ หลักฐาน | `Evidence`, `EvidenceFile`, ฟอร์มหลักฐาน, เก็บงาน (Work Collection) |
| ๒ ตัวชี้วัดและความเชื่อมโยง | `QAIndicator`, `indicatorId`, `indicatorCodes`, `PAIndicator`, `PAEvidenceMapping`, API analyze |
| ๓ กระบวนการประเมิน | `completeness.ts`, `pass-criteria.ts`, `PAAgreement`/Item/Challenge, การให้คะแนน PA |
| ๔ ผลลัพธ์และการพัฒนา | รายงานความพร้อม/Missing/Files, `development-summary.ts`, `pptx-generator.ts`, สรุป PA ครู/ผู้บริหาร |

---

เอกสารนี้ใช้เป็น **กรอบ Logic หลัก** สำหรับการออกแบบฟีเจอร์และอธิบายการทำงานของระบบให้ชัดขึ้น
