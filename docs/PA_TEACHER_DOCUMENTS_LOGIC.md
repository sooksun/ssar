# Logic & Database: PA 1/ส, PA 2/ส, PA 3/ส (ของครู)

## ความต้องการทางธุรกิจ

- **ครู 1 คน** สามารถเพิ่ม **PA 1/ส, PA 2/ส, PA 3/ส** ได้ **1 ชุด (1 ครั้ง) ต่อคน ต่อโรงเรียน ต่อปีการศึกษา**
- ถ้าโรงเรียนมี **10 ครู** → ระบบต้องรองรับ **10 ชุด** (ครูแต่ละคนบันทึกของตนเอง)
- จึงต้อง **ผูก user id, school id และปีการศึกษา** กับแต่ละชุด

## การออกแบบฐานข้อมูล

### ตาราง `pateacherdocument`

| คอลัมน์หลัก | ความหมาย |
|-------------|-----------|
| `userId` | ครูที่บันทึก (ผูกกับ user ที่ล็อกอิน) |
| `schoolId` | โรงเรียน |
| `academicYear` | ปีการศึกษา (พ.ศ.) |
| `documentType` | PA1, PA2 หรือ PA3 (PA 1/ส, PA 2/ส, PA 3/ส) |

- **Unique:** `(schoolId, academicYear, documentType, userId)`  
  → ครู 1 คน ต่อโรงเรียน ต่อปี มีได้แค่ 1 รายการต่อประเภท (PA1 / PA2 / PA3)  
  → ครู 1 คน = สูงสุด 3 แถวต่อโรงเรียนต่อปี (PA1, PA2, PA3)  
  → 10 ครู = สูงสุด 30 แถวต่อโรงเรียนต่อปี

### SQL ที่เกี่ยวข้อง

- สร้างตาราง (รวม `userId`): `docs/PA_TEACHER_DOCUMENTS_TABLE.sql`
- ถ้าตารางเก่าไม่มี `userId`: รัน `docs/PA_TEACHER_DOCUMENTS_ADD_USERID.sql`

## การทำงานของระบบ (Logic)

1. **GET (โหลดรายการ)**  
   - ส่ง `schoolId`, `academicYear`  
   - ใช้ **userId จาก session (ครูที่ล็อกอิน)** กรอง  
   - ผลลัพธ์: เฉพาะ PA 1/ส, PA 2/ส, PA 3/ส **ของครูคนนั้น** ในโรงเรียนและปีที่เลือก

2. **POST (อัปโหลด/บันทึก)**  
   - ใช้ **userId จาก session** เป็นเจ้าของรายการ  
   - บันทึก/อัปเดตตาม `(schoolId, academicYear, documentType, userId)`  
   - ครูคนอื่นไม่สามารถแก้ไขหรือเขียนทับของครูคนนี้ได้

3. **UI**  
   - แสดงข้อความว่า **「กำลังแสดง/บันทึกของ: [ชื่อครูที่ล็อกอิน]」**  
   - ครูแต่ละคนเห็นและจัดการเฉพาะชุดของตนเอง

## สรุป

- **ผูก user id, school id, ปีการศึกษา** ครบตามความต้องการ
- ครู 1 คน = 1 ชุด (PA 1/ส, PA 2/ส, PA 3/ส) ต่อโรงเรียนต่อปี
- โรงเรียน 10 คน = 10 ชุด (30 รายการถ้าบันทึกครบทั้ง 3 ประเภท)
