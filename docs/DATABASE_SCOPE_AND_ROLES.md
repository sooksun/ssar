# ขอบเขตฐานข้อมูลและระดับผู้ใช้

เอกสารนี้อธิบายการออกแบบฐานข้อมูลให้ยืดหยุ่นตามเงื่อนไขการใช้งาน

---

## 1. หลายสังกัด — สำนักงานเขตพื้นที่การศึกษา (สพฐ.)

- **EducationServiceArea** = สำนักงานเขตพื้นที่การศึกษา (สพป./สพม.)
  - รหัสเขต (`code`), ชื่อ (`nameTh`), จังหวัด (`province`)
- **School** มีฟิลด์ `areaId` (FK ไป EducationServiceArea) — โรงเรียนทุกแห่งในสพฐ. สามารถผูกกับเขตพื้นที่ได้
- รองรับหลายสังกัด: แต่ละเขตมีหลายโรงเรียน; ระบบสามารถมีหลายเขต (หลายสพป./สพม.)

---

## 2. ใช้ได้กับทุกโรงเรียนในสพฐ.

- โรงเรียนใดก็ตามที่ลงทะเบียนในระบบ (ตาราง `School`) และผูก `areaId` กับเขตพื้นที่ จะอยู่ภายใต้โครงสร้างเดียวกัน
- การรายงาน/สรุปทำได้ระดับโรงเรียน และระดับเขต (ผ่านผู้ใช้ระดับ AREA_*)

---

## 3. ใช้ได้ต่อเนื่องหลายปีการศึกษา — รายงานภาคเรียนละ 1 ครั้ง

- **ปีการศึกษา/ปีงบประมาณ:** ใช้ `fiscalYear` (ปีงบ ต.ค.–ก.ย.) และ `academicYear` (ปีการศึกษา พ.ค.–เม.ย.) ใน Evidence, DevelopmentSummary ฯลฯ
- **ภาคเรียน:** ใช้ `assessmentRound` ใน DevelopmentSummary และรายงานสรุป
  - `assessmentRound = 1` = ภาคเรียนที่ 1 ต่อปี
  - `assessmentRound = 2` = ภาคเรียนที่ 2 ต่อปี
- สรุป/รายงานทำได้ต่อเนื่องหลายปี โดยกรองตาม `fiscalYear` และ `assessmentRound`

---

## 4. ระดับผู้ใช้ (User Levels)

| ระดับ | รหัส Role | คำอธิบาย | ขอบเขตข้อมูล |
|--------|------------|----------|------------------|
| ครู | TEACHER | ใช้สารสนเทศและบันทึกข้อมูลโดยตรง (ref3) | ตามโรงเรียนที่ผูกใน UserSchoolRole |
| ผู้อำนวยการโรงเรียน | SCHOOL_DIRECTOR | นำข้อมูลที่สังเคราะห์จากครูมาบันทึกเพิ่ม จัดทำรายงานเป็นของตนเอง (ref1) | ตามโรงเรียนที่ผูก |
| ผู้ดูแลระบบระดับโรงเรียน | SCHOOL_ADMIN | จัดการระบบระดับโรงเรียน | ตามโรงเรียนที่ผูก |
| ผู้อำนวยการเขตพื้นที่ | AREA_HEAD_OFFICE | ระดับเขตพื้นที่ | เห็นทุกโรงเรียนในเขต (UserAreaRole) |
| ผู้ดูแลระบบระดับเขต | AREA_ADMIN | จัดการระบบระดับเขต | เห็นทุกโรงเรียนในเขต (UserAreaRole) |
| ผู้ดูแลระบบ (เดิม) | ADMIN | ดูแลทั้งระบบ | ทุกโรงเรียน |
| ผู้นำ QA / ผู้ประเมิน | QA_LEAD, ASSESSOR | ตามที่ออกแบบเดิม | ตามโรงเรียนที่ผูก |

- **ระดับโรงเรียน:** บทบาทผ่าน **UserSchoolRole** (userId + schoolId + roleId)
- **ระดับเขตพื้นที่:** บทบาทผ่าน **UserAreaRole** (userId + areaId + roleId) — ผู้ใช้เห็นทุกโรงเรียนที่ `School.areaId = areaId`

---

## โครงสร้างตารางที่เกี่ยวข้อง

```
EducationServiceArea (สำนักงานเขตพื้นที่)
  └── School[] (areaId)
  └── UserAreaRole[] (areaId)

User
  └── UserSchoolRole[] (โรงเรียน + บทบาทระดับโรงเรียน)
  └── UserAreaRole[] (เขตพื้นที่ + บทบาทระดับเขต)

Role (ADMIN, TEACHER, SCHOOL_DIRECTOR, SCHOOL_ADMIN, AREA_HEAD_OFFICE, AREA_ADMIN, QA_LEAD, ASSESSOR)
```

---

## การตรวจสอบสิทธิ์ (Scoping)

- `getUserSchools(userId)` คืนรายการ `sc_id` ของโรงเรียนที่ user เข้าถึงได้:
  - ADMIN → ทุกโรงเรียน
  - UserAreaRole (AREA_HEAD_OFFICE / AREA_ADMIN) → ทุกโรงเรียนที่ school.areaId ตรงกับ area ที่ผูก
  - UserSchoolRole → เฉพาะโรงเรียนที่ผูก
- `canAccessSchool(userId, schoolId)` ใช้ logic เดียวกัน: อนุญาตถ้า user เป็น ADMIN หรือมีบทบาทที่โรงเรียนนั้น หรือมีบทบาทระดับเขตที่ครอบคลุมโรงเรียนนั้น
