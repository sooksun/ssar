## ตารางที่สร้างใหม่ (10 ตาราง)

| ลำดับ | ตาราง | คำอธิบาย | จำนวนข้อมูลเริ่มต้น |
|-------|-------|----------|---------------------|
| 1 | `PAAspect` | 5 ด้านของ PA | 5 รายการ |
| 2 | `PAIndicator` | 15 ตัวชี้วัด | 15 รายการ |
| 3 | `PAIndicatorScale` | เกณฑ์คะแนน 1-4 | 60 รายการ |
| 4 | `PAConsideration` | 3 ข้อพิจารณาส่วนที่ 2 | 3 รายการ |
| 5 | `PAAgreement` | ข้อตกลง PA ของแต่ละคน/ปี | ตามการใช้งาน |
| 6 | `PAAgreementItem` | รายการประเมินแต่ละตัวชี้วัด | 15 รายการ/ข้อตกลง |
| 7 | `PAChallengeItem` | ประเด็นท้าทายส่วนที่ 2 | 1 รายการ/ข้อตกลง |
| 8 | `PAChallengeConsideration` | ผลประเมินรายข้อพิจารณา | 3 รายการ/ประเด็น |
| 9 | `PAEvidenceMapping` | เชื่อมหลักฐานกับ PA | ตามการใช้งาน |
| 10 | `PASummary` | สรุปผลการประเมิน | 1 รายการ/คน/ปี |

## โครงสร้าง PA

### ส่วนที่ 1: ข้อตกลงพัฒนางาน (60 คะแนน)

```
P1: ด้านการบริหารวิชาการและความเป็นผู้นำทางวิชาการ (6 ตัวชี้วัด)
   ├── 1.1 การวางแผนพัฒนามาตรฐานการเรียนรู้
   ├── 1.2 การจัดทำและพัฒนาหลักสูตรสถานศึกษา
   ├── 1.3 การพัฒนากระบวนการจัดการเรียนรู้
   ├── 1.4 การส่งเสริมสื่อ นวัตกรรม และเทคโนโลยี
   ├── 1.5 การนิเทศ กำกับ ติดตาม ประเมินผล
   └── 1.6 การศึกษา วิเคราะห์ เพื่อยกระดับคุณภาพ

P2: ด้านการบริหารจัดการสถานศึกษา (3 ตัวชี้วัด)
   ├── 2.1 การบริหารจัดการตามกฎหมายและหลักบริหารที่ดี
   ├── 2.2 การบริหารกิจการผู้เรียน
   └── 2.3 การจัดระบบดูแลช่วยเหลือผู้เรียน

P3: ด้านการบริหารการเปลี่ยนแปลงเชิงกลยุทธ์และนวัตกรรม (2 ตัวชี้วัด)
   ├── 3.1 การกำหนดนโยบาย กลยุทธ์ และนวัตกรรม
   └── 3.2 การบริหารการเปลี่ยนแปลงและนวัตกรรม

P4: ด้านการบริหารงานชุมชนและเครือข่าย (2 ตัวชี้วัด)
   ├── 4.1 การสร้างและพัฒนาเครือข่าย
   └── 4.2 การจัดระบบการให้บริการ

P5: ด้านการพัฒนาตนเองและวิชาชีพ (2 ตัวชี้วัด)
   ├── 5.1 การพัฒนาตนเองและวิชาชีพ
   └── 5.2 การนำความรู้มาใช้พัฒนาสถานศึกษา
```

### ส่วนที่ 2: ข้อตกลงประเด็นท้าทาย (40 คะแนน)

```
C1: วิธีดำเนินการ (20 คะแนน)

C2.1: ผลลัพธ์ - เชิงปริมาณ (10 คะแนน)
   └── พิจารณาการบรรลุเป้าหมายเชิงปริมาณ

C2.2: ผลลัพธ์ - เชิงคุณภาพ (10 คะแนน)
   └── พิจารณาการบรรลุเป้าหมายเชิงคุณภาพ
```

## การคำนวณคะแนน

### สูตรคำนวณ

```
ส่วนที่ 1 (60 คะแนน):
  คะแนนเฉลี่ย = (ผลรวมคะแนน 15 ตัวชี้วัด) / 15
  คะแนนส่วนที่ 1 = (คะแนนเฉลี่ย / 4) × 60

ส่วนที่ 2 (40 คะแนน):
  C1 (วิธีดำเนินการ)     = คะแนน × 5    (สูงสุด 20)
  C2.1 (เชิงปริมาณ)     = คะแนน × 2.5  (สูงสุด 10)
  C2.2 (เชิงคุณภาพ)     = คะแนน × 2.5  (สูงสุด 10)
  คะแนนส่วนที่ 2 = C1 + C2.1 + C2.2

คะแนนรวม = ส่วนที่ 1 + ส่วนที่ 2 (100 คะแนน)

เกณฑ์ผ่าน: คะแนนรวม ≥ 70 (70%)
```

### ระดับการประเมิน

| คะแนน | ระดับ | คำอธิบาย |
|--------|-------|----------|
| 1 | ปฏิบัติได้ต่ำกว่าระดับที่คาดหวังมาก | ต้องปรับปรุงอย่างมาก |
| 2 | ปฏิบัติได้ต่ำกว่าระดับที่คาดหวัง | ต้องปรับปรุงเพิ่มเติม |
| 3 | ปฏิบัติได้ตามระดับที่คาดหวัง | ดำเนินการตามเกณฑ์ |
| 4 | ปฏิบัติได้สูงกว่ารระดับที่คาดหวัง | มีนวัตกรรม/แนวปฏิบัติดีเยี่ยม |

## ขั้นตอนการติดตั้ง

```bash
# 1. รัน SQL Migration
cd prisma/migrations/add_pa_tables
mysql -u root -p ssar < migration.sql

# 2. อัพเดท Prisma Schema
# แก้ไข schema.prisma เพิ่ม models จาก schema-pa-merged.prisma

# 3. สร้าง Prisma Client
npx prisma generate

# 4. ตรวจสอบความถูกต้อง
npx prisma db pull
npx prisma validate
```

## ตัวอย่างการใช้งานหลัก

### 1. สร้างข้อตกลง PA

```typescript
import { createPAAgreement } from '@/lib/pa-utils';

const agreement = await createPAAgreement({
  schoolId: BigInt(1),
  userId: BigInt(123),
  fiscalYear: 2567,
  startDate: new Date('2024-10-01'),
  endDate: new Date('2025-09-30')
});
```

### 2. เชื่อมหลักฐานกับ PA

```typescript
import { mapEvidenceToPA } from '@/lib/pa-utils';

await mapEvidenceToPA({
  evidenceId: BigInt(100),
  agreementItemId: BigInt(50),
  note: 'ใช้ประกอบตัวชี้วัด 1.2',
  relevanceLevel: 4
});
```

### 3. บันทึกคะแนน

```typescript
import { savePAEvaluation } from '@/lib/pa-utils';

const result = await savePAEvaluation(
  agreementId,
  {
    itemScores: [
      { itemId: BigInt(1), score: 3, comment: 'ดำเนินการตามเกณฑ์' },
      // ... 14 รายการอื่น
    ],
    c1MethodScore: 4,
    c21QuantScore: 3,
    c22QualScore: 3
  }
);
// result = { totalScore: 85.5, isPassed: true, ... }
```

## สรุป

การออกแบบนี้ช่วยให้:
1. **ใช้หลักฐานร่วมกัน** - หลักฐานชิ้นเดียวใช้ได้ทั้ง QA และ PA
2. **วิเคราะห์แยกมุมมอง** - ดูผลจากหลักฐานชิ้นเดียวกันในมุมมองต่างๆ
3. **ประหยัดทรัพยากร** - ไม่ต้องอัพโหลดหลักฐานซ้ำ
4. **ยืดหยุ่น** - สามารถเชื่อม/ยกเลิกการเชื่อมได้ตลอด
